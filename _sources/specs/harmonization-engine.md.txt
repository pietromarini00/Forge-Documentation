# SchemaForge: Harmonization Engine

## Product Specification v0.3

---

## Executive Summary

The **Harmonization Engine** is SchemaForge's service for mapping source dataset fields to canonical schema elements. It combines hybrid retrieval (TF-IDF + semantic embeddings), LLM-based evaluation, and human-in-the-loop curation to achieve high-quality schema mappings at scale.

This service directly addresses the "intake" problem: when new data sources arrive, someone must map each source field to the canonical schema. Currently this is manual, inconsistent, and untracked. The Harmonization Engine automates candidate discovery, provides AI-assisted recommendations, and captures curator decisions to improve over time.

---

## Problem Statement

Organizations harmonizing data from multiple sources face a recurring challenge: mapping source fields to canonical elements.

**Current pain points:**
- Manual matching is tedious (100+ fields per source × multiple sources)
- Keyword search misses synonyms and abbreviations (e.g., "BP" → "BloodPressure")
- No standardized process—quality depends on who does the mapping
- Mappings are lost or poorly documented
- Same mistakes repeated across similar sources
- No feedback loop to improve matching over time

**Result:** Data harmonization is a bottleneck. Each new source requires significant manual effort, and mapping quality is inconsistent.

---

## Solution

The Harmonization Engine provides:

1. **Hybrid Retrieval** — Combine lexical (TF-IDF) and semantic (embeddings) matching to surface relevant candidates
2. **AI Evaluation** — LLM-based assessment of match quality with confidence scores
3. **Curation Interface** — Human review and correction of AI recommendations
4. **Feedback Learning** — Capture curator decisions to identify improvement opportunities
5. **Mapping Management** — Store, version, and export finalized mappings

## Core Concepts

### Source
A dataset being mapped to the canonical schema.

```yaml
source:
  id: "uuid"
  name: "NACC UDS3"
  description: "National Alzheimer's Coordinating Center Uniform Data Set v3"
  file_type: "csv"                    # csv | xlsx | json | parquet
  field_count: 847
  uploaded_at: "2025-01-15T10:00:00Z"
  uploaded_by: "user_id"
  status: "in_progress"               # uploaded | in_progress | reviewed | finalized
  
  # Progress tracking
  fields_total: 847
  fields_matched: 312
  fields_reviewed: 156
  fields_finalized: 89
```

### Source Field
A single field from the source dataset.

```yaml
source_field:
  id: "uuid"
  source_id: "uuid"
  name: "NACCBRAA"                     # Original field name
  description: "Braak stage for neurofibrillary degeneration"
  inferred_type: "integer"            # Detected from data
  sample_values: ["0", "1", "2", "3", "4", "5", "6"]

  # Matching state
  status: "reviewed"                  # pending | matched | reviewed | finalized | no_match

    element_id: "uuid"
    element_name: "path_braak_nft"

    reasoning: "Direct semantic match. Source field NACCBRAA maps to Braak NFT staging..."
  
  # Final decision
  final_match:
    element_id: "uuid"

    curator_id: "user_id"
    curated_at: "2025-01-15T14:30:00Z"

```

### Candidate
A potential match for a source field.

```yaml
candidate:
  element_id: "uuid"
  element_name: "path_braak_nft"

  # AI evaluation (if performed)
  ai_confidence: 0.94
  ai_reasoning: "Strong semantic alignment..."

```

## Features

### F1: Source Ingestion

**F1.1: Upload Source**
- Support CSV, Excel, JSON, Parquet formats
- Auto-detect field types from data samples
- Extract field descriptions from headers or metadata
- Handle large files (100k+ rows) efficiently

**F1.2: Field Extraction**
- Parse field names and normalize
- Infer data types from values
- Calculate statistics (null %, unique values, sample values)
- Detect potential composite fields

**F1.3: Source Metadata**
- Name and describe the source
- Tag with domain/category
- Link to documentation
- Track upload history

---

### F2: Hybrid Retrieval

The Harmonization Engine uses the **shared Retrieval Core** (see [Shared Infrastructure](#shared-infrastructure-retrieval-core)) for all similarity matching operations.

**F2.1: Index Management**
- Build TF-IDF index on canonical schema elements using `TFIDFEngine`
- Generate embeddings for all elements using `EmbeddingEngine`
- Cache indices for performance
- Rebuild on schema updates (via webhook)

**F2.2: TF-IDF Matching**
- Tokenize and normalize field names + descriptions via `TextProcessor`
- N-gram matching (unigrams + bigrams)
- Stop word removal
- Return cosine similarity scores

**F2.3: Semantic Matching**
- Encode source field as embedding
- Cosine similarity against element embeddings
- Handle synonyms and abbreviations
- Support domain-specific models (configurable)

**F2.4: Score Combination**
- Configurable weights via `ScoreCombiner` (default: 40% TF-IDF, 60% embedding)
- Optional: Reciprocal Rank Fusion mode
- Return top-k candidates (default: 15)
- Include component scores for analysis

```python
# Configuration options
@dataclass
class RetrievalConfig:
    embedding_model: str = "all-MiniLM-L6-v2"
    tfidf_weight: float = 0.4
    embedding_weight: float = 0.6
    top_k: int = 15
    use_rrf: bool = False
    include_component_scores: bool = True
```

---

### F3: AI Evaluation

**F3.1: Candidate Assessment**
- LLM evaluates each candidate for semantic match
- Considers: name similarity, description alignment, value compatibility
- Outputs confidence score (0-1) and reasoning

**F3.2: Batch Processing**
- Process multiple source fields efficiently
- Parallel evaluation where possible
- Progress tracking and resumability

**F3.3: Confidence Calibration**
- Track confidence vs. curator acceptance
- Identify systematic over/under-confidence
- Adjust thresholds based on feedback

**F3.4: Configurable Prompts**
- Template-based prompt construction
- Domain-specific instructions
- A/B testing support for prompt variants

---

### F4: Curation Interface

**F4.1: Match Review**
- Display source field with context
- Show ranked candidates with scores
- AI recommendation highlighted
- Accept, reject, or select alternative

**F4.2: Bulk Operations**
- Auto-accept high-confidence matches (threshold configurable)
- Review queue sorted by confidence (low first)
- Batch accept/reject similar patterns

**F4.3: No-Match Handling**

When a source field has no acceptable match among existing canonical elements, the curator has three options:

1. **Mark as Intentionally Unmapped**
   - Field is not relevant to canonical schema
   - Examples: internal IDs, source-specific metadata
   - Recorded with reason code: `not_applicable`, `source_specific`, `deprecated`

2. **Propose New Element** *(Phase C)*
   - Field represents a concept missing from canonical schema
   - Creates a proposal for schema admin review
   - See F4.5 for full workflow

3. **Request Guidance**
   - Curator unsure how to handle field
   - Creates a review request with question
   - Routed to domain expert or schema admin

**F4.4: Value Mapping** *(Phase B)*

The Value Mapping feature enables curators to define how source values map to canonical element values. This is critical when:
- Source uses different encoding (e.g., "Male"/"Female" vs. 0/1)
- Source has additional values not in canonical allowed_values
- Source uses sentinel values for missing data (e.g., 99, -1)

**Transform Types:**

| Type | Description | Example |
|------|-------------|---------|
| `direct` | No transformation needed | age → age |
| `remap` | Value-to-value mapping | "Male" → 0 |
| `formula` | Computed transformation | birth_year → 2025 - birth_year |
| `conditional` | Rule-based transformation | if age < 18: "minor" else "adult" |
| `lookup` | External lookup table | zip_code → state |

**Proposal Workflow:**
1. Data manager creates proposal with element definition
2. System detects similar existing elements
3. Proposal synced to Registry Service
4. Schema admin reviews in Curation Workbench
5. On approval: element created, source field auto-mapped
6. On rejection: proposer notified with reason/alternative

**Proposal States:**
- `draft` — Being edited by proposer
- `pending` — Submitted, awaiting review
- `under_review` — Claimed by reviewer
- `approved` — Element created
- `rejected` — Declined with reason
- `withdrawn` — Cancelled by proposer

**Transform Patterns (Organic Growth):**

Patterns are built organically from curator behavior:

```python
async def check_pattern_promotion(transform: Transform) -> Optional[PatternSuggestion]:
    """
    Check if a transform should be suggested as a reusable pattern.
    Triggered after transform is saved.
    """
    
    # Find similar transforms across all sessions
    similar = await find_similar_transforms(
        transform_type=transform.transform_type,
        definition=transform.definition,
        similarity_threshold=0.9
    )
    
    # If 3+ similar transforms exist, suggest pattern
    if len(similar) >= 3:
        # Check if pattern already exists
        existing = await find_matching_pattern(transform.definition)
        if existing:
            # Increment usage count
            await increment_pattern_usage(existing.id)
            return None
        
        # Suggest new pattern
        return PatternSuggestion(
            transform=transform,
            similar_count=len(similar),
            suggested_name=generate_pattern_name(transform),
            suggested_description=generate_pattern_description(transform, similar)
        )
    
    return None
```

### TextProcessor

Standardizes how element text is prepared for matching.

```python
class TextProcessor:
    """Prepare element text for retrieval."""
    
    @staticmethod
    def normalize(text: str) -> str:
        """Lowercase, remove special chars, normalize whitespace."""
        text = text.lower()
        text = re.sub(r'[_\-]+', ' ', text)  # snake_case → words
        text = re.sub(r'([a-z])([A-Z])', r'\1 \2', text)  # camelCase → words
        text = re.sub(r'[^a-z0-9\s]', '', text)
        return ' '.join(text.split())
    
    @staticmethod
    def build_element_text(element: Element) -> str:
        """
        Combine element fields into searchable text.
        
        Consistent across all services using retrieval.
        """
        parts = [
            element.name,
            element.display_name or "",
            element.description or "",
            " ".join(element.aliases or []),
        ]
        if element.allowed_values:
            # Include enum values for matching
            parts.append(" ".join(str(v) for v in element.allowed_values[:20]))
        
        return " ".join(filter(None, parts))
```

### TFIDFEngine

Token-level lexical matching.

```python
class TFIDFEngine:
    """TF-IDF based text similarity."""
    
    def __init__(self):
        self.vectorizer = TfidfVectorizer(
            lowercase=True,
            stop_words='english',
            ngram_range=(1, 2),
            max_features=10000
        )
        self.matrix = None
    
    def fit(self, texts: List[str]) -> None:
        """Build vocabulary from texts."""
        normalized = [TextProcessor.normalize(t) for t in texts]
        self.matrix = self.vectorizer.fit_transform(normalized)
    
    def query(self, text: str) -> np.ndarray:
        """Get similarity scores against fitted corpus."""
        normalized = TextProcessor.normalize(text)
        query_vec = self.vectorizer.transform([normalized])
        return cosine_similarity(query_vec, self.matrix)[0]
    
    def similarity_matrix(self) -> np.ndarray:
        """Get pairwise similarities for all fitted texts."""
        return cosine_similarity(self.matrix)
```

### EmbeddingEngine

Semantic similarity via dense embeddings.

```python
class EmbeddingEngine:
    """Embedding-based semantic similarity."""
    
    def __init__(self, model: str = "all-MiniLM-L6-v2", cache_dir: str = None):
        self.model = SentenceTransformer(model)
        self.cache_dir = cache_dir
        self.embeddings = None
    
    def encode_batch(self, texts: List[str]) -> np.ndarray:
        """Encode texts to embeddings, with caching."""
        cache_key = self._cache_key(texts)
        if self.cache_dir and os.path.exists(cache_key):
            return np.load(cache_key)
        
        embeddings = self.model.encode(texts, show_progress_bar=True)
        
        if self.cache_dir:
            np.save(cache_key, embeddings)
        
        self.embeddings = embeddings
        return embeddings
    
    def query(self, text: str) -> np.ndarray:
        """Get similarity scores against encoded corpus."""
        query_emb = self.model.encode([text])
        return cosine_similarity(query_emb, self.embeddings)[0]
    
    def similarity_matrix(self) -> np.ndarray:
        """Get pairwise similarities for all encoded texts."""
        return cosine_similarity(self.embeddings)
```

### ScoreCombiner

Combines lexical and semantic scores.

```python
@dataclass
class RetrievalConfig:
    tfidf_weight: float = 0.4
    embedding_weight: float = 0.6

class ScoreCombiner:
    """Combine TF-IDF and embedding scores."""
    
    def __init__(self, config: RetrievalConfig = None):
        self.config = config or RetrievalConfig()
    
    def combine(
        self, 
        tfidf_scores: np.ndarray, 
        embedding_scores: np.ndarray
    ) -> np.ndarray:
        """Combine score arrays."""
        return (
            self.config.tfidf_weight * tfidf_scores +
            self.config.embedding_weight * embedding_scores
        )
    
    def combine_matrices(
        self,
        tfidf_matrix: np.ndarray,
        embedding_matrix: np.ndarray
    ) -> np.ndarray:
        """Combine pairwise similarity matrices."""
        return (
            self.config.tfidf_weight * tfidf_matrix +
            self.config.embedding_weight * embedding_matrix
        )
```

### HybridRetriever Implementation

The Harmonization Engine's `HybridRetriever` uses the shared core:

```python
class HybridRetriever:
    """
    Query-based retrieval for field matching.
    
    Use case: Given a source field, find top-k matching canonical elements.
    """
    
    def __init__(self, config: RetrievalConfig = None):
        self.config = config or RetrievalConfig()
        self.tfidf = TFIDFEngine()
        self.embeddings = EmbeddingEngine()
        self.combiner = ScoreCombiner(self.config)
        self.elements = []
    
    def index_elements(self, elements: List[Element]) -> None:
        """Build indices from canonical elements."""
        self.elements = elements
        texts = [TextProcessor.build_element_text(e) for e in elements]
        
        self.tfidf.fit(texts)
        self.embeddings.encode_batch(texts)
    
    def retrieve(self, query: str, top_k: int = 15) -> List[Candidate]:
        """Find top-k matching elements for a query."""
        query_text = TextProcessor.normalize(query)
        
        tfidf_scores = self.tfidf.query(query_text)
        embedding_scores = self.embeddings.query(query_text)
        combined = self.combiner.combine(tfidf_scores, embedding_scores)
        
        # Get top-k indices
        top_indices = np.argsort(combined)[::-1][:top_k]
        
        return [
            Candidate(
                element=self.elements[i],
                score=combined[i],
                tfidf_score=tfidf_scores[i],
                embedding_score=embedding_scores[i],
                rank=rank + 1
            )
            for rank, i in enumerate(top_indices)
        ]
```

### Registry Client

```python
class RegistryClient:
    """
    Client for Registry Service API.
    """
    
    def __init__(self, base_url: str, api_key: str):
        self.base_url = base_url
        self.api_key = api_key
        self.cache = {}
    
    async def get_schema_elements(
        self,
        schema_id: str,
        use_cache: bool = True
    ) -> List[Element]:
        """Fetch all elements for a schema."""
        cache_key = f"elements:{schema_id}"
        if use_cache and cache_key in self.cache:
            return self.cache[cache_key]
        
        response = await self._get(f"/api/v1/schemas/{schema_id}/elements")
        elements = [Element(**e) for e in response["data"]]
        
        self.cache[cache_key] = elements
        return elements
    
    def invalidate_cache(self, schema_id: str):
        """Invalidate cache for schema (called by webhook)."""
        cache_key = f"elements:{schema_id}"
        self.cache.pop(cache_key, None)
```

## Design Decisions

### 1. Cache Invalidation: Webhooks (Not Polling)
- Harmonization Engine exposes `POST /webhooks/schema-changed`
- Registry Service sends signed webhooks on element/schema changes
- Retry policy: 3 retries, exponential backoff (1s, 5s, 30s)
- Rationale: Immediate invalidation, no wasted polling

### 2. Transform Patterns: Built Organically (No Preloading)
- No seed data for transform patterns
- System tracks transform similarity across sessions
- After 3+ similar transforms, suggest promoting to pattern
- Rationale: Learn from actual usage rather than guessing

### 3. Proposals: Phase C (With Curation Workbench)
- Deferred from Phase B to Phase C
- Rationale: Review workflow requires Curation Workbench UI
- Proposal tables specified but not implemented until UI ready

### 4. Shared Retrieval Core
- Same TF-IDF + embedding approach used by Harmonization Engine and Curation Workbench
- Ensures consistent matching behavior across services
- `TextProcessor`, `TFIDFEngine`, `EmbeddingEngine`, `ScoreCombiner` are shared primitives
- Different interfaces for different use cases:
  - `HybridRetriever.retrieve()` for query → top-k (Harmonization)
  - `DuplicateDetector.detect()` for set → all pairs (Curation)
- Rationale: Consistency, proven algorithms, code reuse
